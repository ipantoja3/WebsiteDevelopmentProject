Colors

I chose a simple color scheme from colorhunt.co. This is a free-to-use website featuring hundreds of free use color palettes for websites. I made some minor modifications, such as removing a gold color that didn't fit particularly well and adding a lighter "selected" color for the numbers below and screen reader selection. These colors are stored in CSS variables to avoid having to type the hex code every time. The background color, #e8dcc4, is saved as "bg"; the selected color, #8AB8AD, is saved as "selected"; the header color, #123f36, is saved as "dark"; and the lighter border color of the header, #2a6b5c, is saved as "light." These colors are contrast-compliant with WCAG, something I'll elaborate on in the WCAG page.

Margins

I greatly struggled with the margins and padding of CSS. I find their implementation comically unintuitive. Firstly, browsers will apply padding and margins to all websites by default that must be manually removed. Secondly, many elements feature their own default padding that must also be indepently removed and ignore the margin/padding settings of their parent containers. Tables, lists, and buttons all do this, requiring more work and troubleshooting from the user. Choosing specific margin/padding sizes also gave me trouble for quite awhile. Margins provide an aesthetically pleasing gap between elements, stopping the text you see from touching the very edge of your screen or the very bottom/top of the header/footer.

Sizing

Originally, at the start of my class, I used px sizing for everything without thinking about it. Then, I opened my first real attempt at a website on my desktop at home and it was completely broken. Why? My laptop screen, that I built the website on, is 1366x768 pixels. My desktop is 1920x1080 pixels. A 5 pixel element will take up a much smaller portion of the screen on my desktop than on my laptop, drastically altering the positioning and relative size of every single element on my desktop. To combat this, I didn't size or position any major elements with px, instead opting for vh and vw. Vh and vw represent a percentage of the screen size, meaning that instead of having to find a pixel amount for 10% of my screen that wouldn't work on other devices, I can use "10vh" and have it adapt automatically to be 10% of the user's view height.
